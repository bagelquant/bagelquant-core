# Graph, cache, lifecycle and execution

Retained older execution-policy receipts cannot veto independently completed
current-policy prefixes with matching relevant parameters. Reuse still requires
current block/input/parameter proofs before any kernel runs. If only obsolete
policies remain, or current consumed proofs are unknown, require explicit
maintenance rather than adopting the old policy or replaying completed history.

The optional finite percentage-change view is private execution preparation,
not a new numerical formula or policy. Keep original read/proof/canonical/output
Domains and all receipt identities. Validate the entire original selected input
and its dense implicit-null coordinates before pruning to all missing output
keys plus each output asset's H preceding admitted keys. Use a public dynamic
Domain with the original calendar and explicit active=True retained keys; dense
alignment must not recreate discarded membership. Only the exact built-in unary
Float64 numeric percentage-change/Date-trace path is eligible; all other types,
static/auxiliary/custom/rolling/ML paths stay unchanged. Admission reserves
working headroom before B-only allocations from already divided, index-debited
limits and holds it through publication. Nonadmission runs the original path;
never retry MemoryError or clear foreign exception frames to manufacture a
resource-release claim. Prove exact values/traces/IDs/history and owned lifetime;
calendar-session counters are not prepared-row or native-RSS measurements.

Core owns LogicalGraphSpec, Graph DSL/merge/resolve, dependency primitives, and
CoreStore SQLite/Parquet implementations at caller-provided paths. It imports no
Data/BT/Workbench. Workbench owns global admission, CPU/RAM detection and pressure
policy; Core only applies explicit local budgets and reports work.

Schema 4 stores one compact `node_completions` row per graph/context/durable node.
`CoreStore.node_completions` reads successful definition/upstream digests,
observation/check dates and the immutable result reference in one metadata query.
`UpdatePlan` adopts only exact matching authority without a value lookup or proof
callback. Missing children construct lazy plans for only their consumed completed
parents. Each durable result advances its flag under graph/state revision fences;
incomplete updates retain these flags while global/branch completion remains a
separate publication. Older historical branches cannot regress the latest flag.
A date alone never proves freshness after definition, Domain or dependency edits.
Update headers, admitted contexts and node-result relations are normalized and
published atomically. Indexed completion/request queries never scan enclosing
receipt JSON. Materialization candidate headers bind the original content,
implementation, policy, parameters, dates and checkpoint availability. Planners
filter these records before reading selected manifests/checkpoints; exact public
update bodies and identities are reconstructed from the registered relations.
Finite read contexts admit bounded thread-safe immutable manifest/index memos;
they expire on exit and never cache revision fences or missing optional indexes.
Explicit audits start fresh metadata verification and check candidate/original bindings.
Successful composed-source binding checks share that same finite byte budget;
their keys bind immutable original content. Failed checks are never retained.
Closing publication transactions and explicit full audits never borrow read-context
successes. Their fresh bounded scopes deduplicate shared admission/ancestry within
one transaction, using the existing reserve and expiring before that scope ends.
Cached ancestry includes proof-only parents; cycle checks precede cache hits.
Older schemas are incompatible; there is no migration reader or implicit reconstruction.

Deterministic zero-history lazy built-ins form bounded regions. Requested roots,
explicit `persist_nodes`, shared operator boundaries, finite rolling, causal,
stateful, model, custom and eager boundaries remain durable. Exact intermediate
day/Domain/type/trace indexes are committed atomically with each durable region
block; a seal binds complete logical coverage to its durable composite. Update
receipts expose real numerical results and a separate transient-node-to-boundary
`coverage` map. `CoreStore.update_covers` validates registered authority; applications
must not infer missing artifacts or trust an independently supplied coverage map.
Physical region choices never enter numerical policies or material keys. Append,
repair and retry verify certificates before reusing original canonical blocks;
unknown complete-history proofs block before numerical work. Internal outputs
requested later become durable while existing completed roots remain reusable.
Sparse region outputs use one multi-output collection with coordinate-keyed
trace joins. Their validated frames remain local to the admitted operation;
sparse row presence never comes from a dense cache. Grouped proof hashing may
share physical row hashes only while preserving the original per-group schema,
height, width and ordered row-hash bytes, including interleaved date groups.

Operation-local preparation shares actual immutable Domain windows, all admitted
halo schedules, successful interval proofs and fitting parent slabs. Its charged
byte budget reserves at most one quarter of admitted cache memory, reducing
local runtime cache accordingly. There is no fixed 64 MiB ceiling: larger caller
allocations can retain useful parent slabs instead of repeatedly decoding them.
Each execution restricts that operation's reserve to its actual worker share;
a smaller admission cannot later be enlarged. Eviction/zero cache retain the
bulk read path. Per-key single-flight work never holds a global metadata lock
during collection. Publication expires cached values; no missing proof or mutable
revision guard is cached. Small immutable proofs and exact window signatures are
protected from large coordinate/value entries within the same total reserve.
Large raw metadata bodies cannot evict compact authenticated owner bindings,
admissions or ancestry. Interval proofs reuse the validated owner/content binding
without re-decoding a complete historical manifest. Update promotion retains
this reserve until its fresh closing verification completes, then expires it.
Signature keys weakly retain the actual Domain identity, never an opaque signature
or a source's coordinate allocation. Generic rolling canonical warm starts and resets stay
unchanged even when an exited asset makes them expensive.
For admitted stored parents, align slab starts to the original 32-session
calendar boundaries and include the extra historical prefix in admission.
Never extend a slab beyond the requested end. Filter retained prefix rows out
before rebinding the exact numerical window. External, zero-cache and bulk
reads retain their original bounds; alignment changes no proof or kernel reset.

`CoreStore.publication_context` initializes once per finite write operation and
expires on exit. Every writer retains schema/revision/publication checks, and a
replaced metadata file fails closed. Read-only planning never enters that context.
Optional `native_admission` and `kernel_dispatch` belong to caller execution policy.
Finite/region work descriptors contain typed explicit staging references and local
limits, never mutable plans or stores. `compute_finite_work` computes only; the
coordinator validates result types/traces, fences cancellation/revisions, publishes
and advances completion. Fresh process/native setup, worker counts and machine
admission remain caller-owned. Staging expires on success, failure or cancellation.

`plan_update(causal_inputs=..., input_version_loader=..., input_scope_proof=...,
causal_output_domains=...)` admits typed CausalInputWindow versions in the same
update engine. Effective known_at/revision precedence comes from the source;
null versions and late-first natural keys are retained. Source coverage may be
larger than the published causal coordinate union. Interval keys bind scoped
as-of proofs and historical output membership, not future source assets/keys.
Normal appends share 32-session batches; late old-observation visibility splits
only affected output ranges and reselects complete finite dependency halos.
Calendar-dense temporary windows preserve null suspension sessions. Version
buffers retain bounded halos, acquire new observation ranges once under frozen
ceilings, and never create decision×lookback×asset historical tensors. Published
node values and completion flags remain Core authority; no application-specific
Risk formula or provider/storage dependency belongs in this mechanism.

`input_definition_identities` admits stable source numerical-definition evidence
per context/input, separately from changing content and scoped as-of tokens.
When supplied it covers exactly admitted contexts and selected input keys.
Causal materialization/completion/block keys bind only relevant ancestors. A
source implementation change creates new authority without deleting original
history; an unchanged source definition never excuses unproven history. Do not
bind full frozen receipts, dynamic content/cutoffs, display text or resources as
source definition identities. Public causal policy version 2 covers this contract.

Logical identity excludes names, app IDs, Domain, source versions and hardware.
Material keys include relevant evidence, Domain, implementation/kernel and numerical
context. Source identities prove immutable values/traces; no unproven reuse.

Use fixed 32-session finite receipt/proof blocks with a caller anchor. Prove all
parent values, coordinates, dynamic membership and availability for block reuse.
Declared checkpoint replay requires unchanged complete parent prefixes, preserves
full calendar/training context and merges audits/artifacts. For calculation changes,
unknown/unsafe prefix evidence requires an actionable plan or explicit proof
maintenance, never silent full-history replay or unproven reuse. Never substitute
observation endpoints for information cutoffs. Workers and physical batches are neutral.

Unchanged numerical definitions update only new/affected coordinates and reuse
completed blocks/checkpoints, old fit events and causal state for portfolio targets. Keep
necessary lookback reads distinct from recomputed output. New cutoffs, enclosing
receipts/Domain extensions and unrelated global counters are not full-rebuild
reasons. Full computation is initial materialization or a relevant definition,
operator implementation or numerical-parameter change. Preserve scheduled new
fits, maturity/embargo/seed semantics and all old model evidence. Test append and
local repair against a full reference, with call/date/fit instrumentation proving
unchanged historical work does not run; record current implementation gaps.

Closed cold initialization may share one ordinary numerical invocation across
at most eight consecutive blocks only when exact completed Core direct parents,
original per32 proofs, no own history, supported native kernel/version and
explicit metadata/dense-row/physical-partition resource admission are established.
Keep one Graph/runtime/publisher path and every original block key, Domain,
content and trace identity. External loaders and any retained own history keep
the original individual-block path. Footer/schema preflight is explicit admitted
consumption under its reservation, never normal metadata prerequisite work;
unsupported types may select the original path only before body consumption.
Errors after admission propagate without replay. Count actual runtime/input work
truthfully and document the changed cold failure granularity. Preserve durable
blocks on cancellation, veto coalescing on retry, reject competing frontier
changes and close owned buffers before restoring limits. Native/RSS bounds and
arbitrary foreign traceback cleanup are not implied by soft admission estimates.
Do not change retained canonical proof scopes or material keys merely to reduce
numerical reads. Narrow a missing output's numerical window only for kernels
with proven exact value/trace independence from earlier state. Count admitted
membership coordinates, including nulls, and preserve old observations needed
by reentering assets. Permanently exited assets absent from the missing output
must not extend such a window. Other finite rolling kernels may depend on
earlier floating-point accumulator state and retain their canonical warm read.
Built-in `lag` uses a calendar-only numerical window because its runtime shifts
keys on the complete parent calendar, including empty dates. Read `periods`
preceding calendar sessions; older admitted observations cannot contribute to
this output interval, even after sparse reentry. No membership-query index is
needed. Keep canonical proofs, Date traces and sparse missing-value behavior;
do not apply this rule to generic rolling or recursive state.
For dynamic exact-window finite execution, an operation-local coordinate index
may answer the same canonical and numerical date queries from the existing
asset/time sort. Admit owned date, offset and calendar buffers against the
already-divided worker cache before constructing them, and use the same reduced
limits for full/window input loaders and Runtime. Construction scratch has a
separate conservative admission estimate against the original noncache working
headroom; it is not a native RSS guarantee. Nonadmission retains the original
queries. Do not change read dates, proof scopes, numerical membership or work
counters, retain values in the index, or retry failures with another path.
Clear Core-owned buffer fields and temporary frame/array aliases before restoring
resource limits, including cancellation and retained exception tracebacks. Use
direct array methods where equivalent to avoid extra Python wrapper references.
Core never clears foreign traceback frames or rewrites exceptions: arbitrary
library or caller locals can retain their own references. Completed receipt hits
allocate no index; an
interrupted all-block reassembly can allocate it while running zero kernels.
Old fits are reusable only with unchanged complete features/labels/samples,
availability/maturity, embargo, seed and numerical parameters. Repair affected
fit events/predictions on relevant input revision. Cross-sectional impact covers
all affected-date members; recursive state replays the affected suffix from a
valid preceding checkpoint. Proven all-history impact is an explicit blocked
plan under this policy, not an implicit full fallback or fake definition edit.
Canonical Date columns keep an identity normalization expression so observation
window predicates reach persisted Parquet scans before decompression. Real String/
Datetime conversions remain explicit; values, traces and material keys are unchanged.

Global updates freeze graph/state revisions and every registered Domain context.
All active computed nodes must succeed before the global pointer advances. Branch
receipts do not advance it. Failures/cancellation/CAS conflicts retain cache only.
Sleep atomically cascades downstream across contexts and is checked at merge,
admission, execution and publication. Wake is explicit and atomic with active
upstream prerequisites. Cached values never bypass sleep; historical reads remain.

CoreStore owns type/Domain/trace/checkpoint/audit/artifact integrity, inventory,
recovery and cleanup. Public receipt APIs hide backend file locations from apps.
`describe`, `describe_update` and `describe_evidence` validate committed metadata
without hashing numerical files or claiming a current byte audit. `read_values`
decodes selected typed Domain/value partitions without implicit byte audits.
Bounded value reads validate persisted canonical Domain schemas and select
calendar/dynamic membership observation rows before constructing a Domain;
they must not validate or sort the complete historical coordinate grid for each
small value window. Keep invalid null observation keys visible to typed validation.
Static asset vectors remain complete. Empty calendar selections return typed
empty values/traces after consumed-schema validation, without inventing a date.
Unbounded reads and explicit integrity APIs still consume the complete Domain;
out-of-window duplicate coordinates remain an explicit full-audit concern.
This view optimization changes no numerical receipt, policy or interval identity.
Ordinary finite UpdatePlan consumers acquire eligible published CoreStore parents
with the same bounded `read_values` API, retaining the already selected numerical
halo and full calendar/proof scopes. Eligibility requires matching frozen planned
and completed receipt identities and the expected Node identity/Domain. Unsaved,
differently identified or custom-store Nodes retain their original lazy path;
contradictory authority and missing/corrupt admitted receipts never fall back.
The scoped Node preserves its original ValueType and trace identity before the
existing local proof rebinding. Only the finite call opts in: checkpoint,
independent-period Prediction, causal and generic paths retain their input-reader
sentinels and loading rules. No value cache, new budget or integrity audit is added.
This consumption uses selected Domain/schema/key/value validation, which can
reject damage earlier or wrap errors differently from a deferred published plan.
Unconsumed damage remains an explicit full-audit or other existing-phase concern;
ordinary reads do not certify unchanged bytes. Valid immutable originals preserve
the exact values, traces, block/materialization identities and historical reuse.
`evidence(channels=...)` reads only requested auxiliary channels. Region-root
evidence descriptions and reads follow sealed transient logical keys to their
retained durable ancestors; fusion must not hide model audits, checkpoints or
auxiliary artifacts. Explicit full
integrity/update verification covers every saved channel and compares optional
interval indexes to original evidence. Ordinary exact execution uses published
metadata/lazy typed plans; only missing-node consumption loads numerical inputs.
Admit each missing finite/region interval from immutable scoped input and all
retained output frame estimates, including conservative temporary/copy overhead,
before numerical source reads. Use the actual local memory share. Oversized work
fails with an actionable `MemoryError`, retaining old receipts; no inline bypass
or replay to introduce persistence boundaries is permitted. Workers recheck the
positive descriptor estimate against their own frozen share before staged reads.
Optional interval proofs include full calendar, membership, empty days, values and
trace/type channels. Completed finite/checkpoint paths with unknown proof or
unprovable relevant parameter/policy scope require explicit maintenance, never
silent historical replay. Stateful contracts declare checkpoint_history read
halos and optional checkpoint_validator structural checks. Reuse original typed
value references and cumulative trace carry; preserve full fit calendars/anchors.
Same-boundary receipt changes with proven identical input perform no source read
or kernel. Historical `index_plan/build_index` maintenance is explicit
and never rewrites manifests. Finite read-context audit proofs expire on exit.
Graph revision guards always read fresh committed state.
Initialization enables WAL explicitly; metadata and graph reads use mode=ro,
query_only transactions and never create graphs or perform recovery.
reference_publication fences Core state while an application commits an immutable
receipt reference in its own transaction; no distributed commit or rollback.
Cleanup preserves committed historical evidence and only reclaims verified
unreferenced completed generations. New storage rejects old schemas.

CoreStore.inspect is a public read-only readiness contract for application setup.
Missing storage is uninitialized; mismatched versions, tables or required columns
are incompatible. Neither inspection nor construction initializes or recovers
storage. The public inspection.open_metadata_snapshot primitive reads stable
metadata/WAL copies in a private system temporary directory; source SQLite/WAL/
SHM remain unchanged. BT may reuse this public Core mechanism. Temporary copies
are removed after inspection and never become a second storage authority.
Active/hot rollback journals are unreadable without explicit owner recovery;
never accept spilled uncommitted schema pages. Include journal identity in
snapshot stability checks; invalidated zero-header PERSIST journals are readable.

`CoreStore.inspect(runtime=True)` and `open_metadata_snapshot(..., runtime=True)`
explicitly use ordinary mode=ro SQLite coordination, query_only and one pinned
committed read transaction, respecting WAL and concurrent writer locks. Runtime
callers permit SQLite WAL/SHM coordination; no copy, initialization or recovery.
Abandoned hot journals requiring recovery fail closed on the read-only connection.
Default offline inspection remains source-untouched and rejects active/hot journals.

Explicit `plan_input_proof_rebind` validates frozen original input projections
and registers immutable Core-owned admission metadata; its planning name does
not make it a read-only preview. Normal Graph planning/prerequisite paths never
call it. `apply_input_proof_rebind` preserves original values/receipts and checks
admission before cache reuse and at publication. All reads/audits of rebound

prove exact consumed values, coordinates, type and traces; Core verifies original

equality or fabricate old source bindings.

The same API's `mode="cutoff_normalization.v1"` admits a complete deterministic
stateless closure over the exact completed output interval when only a later
information cutoff is lowered. Bind both complete external input sets to exact
source-owner projections and reproduce every ordinary canonical key/context.
Verify actual coordinates, parameters, policies, original normalized update
authority, durable results and all transient region members/blocks. Publish
reference-only successors; preserve original values, keys, seals and monotonic
completion flags. Recheck original/admission/block ancestry on apply, reads and

Explicit `cutoff_tail_repair.v1` is a bounded maintenance admission for one potentially changed
final session with exact source-owned prefix equality and unchanged full canonical
recipes, Domains and durable boundaries. Only supported causal pointwise built-ins,

Recheck admitted proof ancestry through every value reference. Same durable keys

Domain reference publication selects an original-content-bound indexed receipt
among registered receipts with the same Domain identity, using the same owner
selection in preparation and the closing writer. Validate the actual ordered
coordinates and binding; missing proofs require explicit index maintenance and
corrupt selected proofs fail. Never decode old Domain files to warm an index.

The generic undeclared-history branch rejects a cache miss for completed work
in the same registered context and numerical implementation unless changed
relevant parameters are proven. Missing completion authority or unknown old
parameter bindings require explicit recovery/maintenance before any input load
or kernel. Independent new contexts retain initialization semantics.
Adjacent change operators declare history=1 and bounded ffill declares its
nonnegative limit; unbounded/future fill stays unsupported. Explicit
`finite_contract.v1` maintenance authenticates an original generic key/context,
completed update, source projections and typed indexed coordinates, then
publishes only canonical references to original values. Its aggregate retains
every block and original indexes; same-context completed ancestry and current
block proofs remain required. Never invoke this certification from ordinary
updates or manufacture transient-region originals. Preserve all old receipts.
`top_n`, `equal_weight`, public Identity and EqualWeight Prediction factories

periods; the same Runtime first updates statistics, then calculates exactly their
dependent predictions. Keep the complete period axis, original IC or regression

Statistics caches are distinct from complete numerical receipts and survive

Cold finite initialization estimates output rows from admitted active coordinates
before history-query or candidate Domain work. A private per-node LRU retains at
most eight successful Date starts under exact canonical origin and endpoint;
charge its bounded objects under P, clear on exit and never cache errors, values,
Frames or proof authorities. Sparse reentry forbids a first-origin monotonic
shortcut. Parent sizing may use global asset/string upper bounds plus every
overlapping physical row count, preserving conservative M/C/R admission and the
original public Domain/proof/typed/publication path. Unknown bounds, allocation,
metadata or consumed-value failures never trigger a caught-error replay. Retained
history and ordinary repeats do not enter this cold planner. No public resource
usage key, persistent identity or configuration flag is added.

Private count-only metadata may binary-search scalar Dates on already resident
normalized sorted axes. Count dynamic keys from the active membership Date
column, including off-calendar dates and extra assets; calendar sessions are a
different count. Reuse the already-owned equal-parent calendar list for planner
rectangles and exactly three counter-only scopes. Preserve empty-calendar
errors. Do not convert/rechunk/collect a full column or retain a new array,
index, view or cache. Release new borrowed lookup aliases on error and success;
never clear foreign traceback frames or catch/replay allocation failures.
Counts/endpoints/opaque identities do not prove membership or typed authority.
Real window/hash/proof/publication/read/Node scopes and P/R/A/index reservations
stay unchanged. Scalar lookup source alone proves no native RSS or latency
bound; isolated Root checks and measurements remain required.
